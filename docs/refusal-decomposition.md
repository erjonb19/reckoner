# Refusal decomposition

Generated by `python -m pipeline.levers` from `summary/`. Changes no result;
every count is one gold already published.

Across 6 reconciled systems: **286,599,414 candidates, 15,123,140 pairs, a pooled comparable share of 5.28%.** The other 271,476,274 were refused, and each refusal carries a reason.

## Read this first

- **Lift is an upper bound**: every refused candidate of a reason becoming a pair.
  Feasibility discounts it, and feasibility is a stated judgement, not a measurement.
- **Candidates are counted after the carrier-level fan-out (#70).** A hospital rate
  meeting 290 plan-level payer rates is 290 candidates, for every reason alike.
- **`no payer-side counterpart` is counted per hospital rate**, not per comparison.
  Resolving one creates one or more comparisons, so its lift is a floor.
- 162,138,225 candidates carry no carrier (NYU Langone): gold written
  before #63 and not yet rebuilt. They are shown as `(not attributed)`, never
  guessed.

**Plan matching lifts comparable share by zero, by construction.** An unresolved
plan is an explanation on a pair that formed, never a refusal: the join keys on
carrier, not plan. What it moves is the 42.48% of pairs
whose only explanation is `plan_unresolved`, making them explained or unexplained.
Under #70's option (b), with plan in the join key, it would also cut the fan-out
and shrink the denominator. That is a change of definition, measured separately.

**Vintage tolerance and setting normalization lift it by zero here** because no
candidate was refused as `vintage_too_far_apart` or `different_setting`. Setting
is part of the join key, so a setting mismatch surfaces as `no payer-side
counterpart` instead, inside the in-corpus row below.

What each lever assignment rests on:

- **different_billing_class → billing class**: mostly a professional rate meeting an institutional one, which are different services. Only the share where the hospital left billing class blank and the mart assumed facility is recoverable, and gold does not record that share.
- **tic_exempt_product → none**: Medicare Advantage and Medicaid rates exist only in hospital files; Transparency in Coverage exempts them by rule. A correct refusal.
- **no payer-side counterpart → unattributed**: written by an image that predates carrier-grain refusals (#63); rerunning the system attributes it.
- **mixed_rate_kind → methodology normalization**: a percentage against a dollar amount; percent-of-charges converts with the gross charge the hospital publishes in the same file.
- **no payer-side counterpart → none**: a real carrier with no payer file here (Healthfirst, MetroPlus, Fidelis, ...). Adding carriers is coverage, not a fix to the reconciliation.
- **no payer-side counterpart → modifier/setting normalization**: the carrier is in the payer corpus but published no rate at this facility, code and setting. Some share is a setting or facility bridge the join missed; most is the payer genuinely not listing the code there, and gold cannot split the two.
- **incompatible_methodology → methodology normalization**: a per diem against a case rate needs a length of stay neither file publishes.
- **no payer-side counterpart → payer/plan name matching**: the hospital's payer string did not resolve to a canonical carrier (for example 'local', 'connecticare', 'northwell direct'). Some would resolve to a corpus carrier and pair; many name carriers the corpus does not hold.
- **zero_rate → none**: a $0 negotiated rate on one side is a placeholder in the filing, not a price.

judgement dressed as a number, and is here only so the levers can be ranked.

**The billing-class column is the finding.** 70.92% of
every candidate is a professional rate meeting an institutional one, or the reverse.
The join keys on facility, code, carrier and setting but not billing class, so it
builds these comparisons and then refuses them. That is the same shape as #70: the
denominator is inflated by construction. Keyed on billing class, the pooled share
would be 18.15% rather than 5.28%, with **no pair
gained**. So billing class tops the lever table by size, but most of it isn't
recoverable. It is a definition to decide, beside #70, not a fix to build.
